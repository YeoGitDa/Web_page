# 리크루팅 화면 구성안

## 1) `/recruit` 모집 랜딩

- 목적: 사용자에게 부원 지원과 인력풀 등록의 차이를 즉시 이해시키기
- 섹션:
  - Hero: 상시 모집 메시지 + 분리 원칙
  - 선택 카드 2개: 부원 지원 / 인력풀 등록
  - 제출 안내: 자동 전송 또는 JSON 백업 흐름
- CTA:
  - `부원 지원서 작성`
  - `인력풀 등록`

## 2) `/recruit/member` 부원 지원서

- 목적: 정규 부원 선발용 정보 수집
- 필수: 이름, 학번, 전공, 연락처, 지원동기, 동의
- 선택: 이메일, 관심분야, 기술스택, 프로젝트 이력, 기대점
- 제출 결과:
  - 성공 메시지
  - 미연동 시 JSON 백업 안내

## 3) `/recruit/talent-pool` 인력풀 등록

- 목적: 프로젝트/대외활동 인력 매칭용 정보 수집
- 필수: 이름, 소속(학번), 연락처, 참여희망유형, 동의
- 선택: 이메일, 가능 시간, 역량 요약, 기타
- 제출 결과:
  - 성공 메시지
  - 미연동 시 JSON 백업 안내

## 4) 공통 UX 원칙

- 상단 고정 내비: 메인/모집홈/부원/인력풀
- 톤 구분: 부원(emerald), 인력풀(sky)
- 모바일 우선: 단일 컬럼, 명확한 필수 항목 표시
- 실패 대비: 서버 미연동 상태에서도 데이터 유실 방지
